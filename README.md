# XQuant 策略研究

`Python 3.12+` · `Node.js ≥ 18` · `Vite 7` · `React 18`

XQuant 是一个量化策略研究项目，核心思路是"**资产配置 + 趋势增强**"：用一组低相关资产做底座，再叠加趋势信号做小幅增强。

项目不只比较回测收益。每个实验都会检查回撤、参数敏感性、交易成本、执行延迟和不同市场阶段的表现，目的是找到**值得继续跟踪的结构**，而不是挑出一条看起来最漂亮的历史曲线。

> 当前统一结论：两个候选都值得进入纸面跟踪，但都**不建议直接实盘**。本项目仅用于研究与学习，不构成投资建议。

## 策略工作原理

两个策略都采用"**核心 + 卫星**"结构。核心仓位负责长期资产配置，卫星仓位只做有限增强。这样即使增强信号失效，也不会让单一资产或单一模型控制整个组合。

核心都从沪深 300、纳指 100 和黄金的 **RiskParity（风险平价）** 出发。它不是简单地各买三分之一，而是参考近期波动分配仓位：波动大的资产少配，波动小的资产多配，尽量避免某一个资产贡献绝大部分风险。

### BTC SuperTrend 卫星

BTC 上涨阶段可能给传统资产组合增加新的收益来源，但下跌通常又快又深。因此只用小仓位参与趋势，并通过开关和仓位上限控制损失，而不是长期重仓 BTC。

具体做法是用 **SuperTrend**——一条根据价格和近期波动计算的趋势线——作为开关。它不预测 BTC 会涨到哪里，只回答一个更简单的问题：当前更像上涨趋势，还是应当回避的阶段。

```text
BTC 收盘价在 SuperTrend 线上方 → 卫星仓位买入 BTC
BTC 收盘价跌到线下           → 卫星仓位转为现金
```

三资产 RiskParity 始终是主体，BTC 只占 5%、7.5% 或 10% 的仓位上限。震荡市场中开关可能反复切换，因此并不是稳赚的买卖信号。

### Theme Alpha 低波趋势卫星

趋势具有一定延续性，而在同样有趋势的资产中，路径较平稳的品种通常更容易持有。但趋势突然反转或市场来回震荡时，这种筛选也会滞后，因此只做卫星，不承担整个组合的收益和风控责任。

基于这个假设，**低波趋势（Low-Vol Trend，LVT）** 先确认趋势，再从合格资产中挑选相对平稳的品种：

1. 价格高于 60 日均线，排除明显的中期下行趋势。
2. 过去 63 日收益为正，确认资产不只是低波动，而且有向上的惯性。
3. 在通过前两关的主题 ETF 中，选择近 60 日波动率最低的 3 个。
4. 入选资产再按风险平价分配，并限制单个资产的最高权重。

Theme Alpha 用 80% 核心仓位维持多资产底座，只用 20% 做 LVT 主题增强。当沪深 300 或纳指 100 跌破各自的 200 日均线时，对应核心仓位转为现金。

## 目前结论

> **数据截至 2026-06-24**。以下指标均基于回测，不代表未来收益。

### BTC SuperTrend 卫星

在传统三资产组合中加入小仓位 BTC 趋势跟踪，历史上提高了年化 3–5 个百分点，回撤没有明显增加。主要样本为 2016-06-21 至 2026-06-23。

| 策略变体 | 年化收益 | 最大回撤 | 夏普 | 卡玛 |
|---------|-------:|-------:|----:|----:|
| 三资产 RiskParity（基准） | 15.71% | -13.53% | 1.36 | 1.16 |
| BTC 5% 仓位上限 | 18.23% | -12.93% | 1.58 | 1.41 |
| **BTC 7.5% 仓位上限（推荐）** | **19.49%** | **-12.75%** | **1.67** | **1.53** |
| BTC 10% 仓位上限 | 20.73% | -12.81% | 1.73 | 1.62 |

- 历史表现最好的是 **BTC 10% 仓位上限**，但它对 BTC 未来继续提供趋势收益的依赖也最强。
- 综合收益、回撤和仓位稳定性，**BTC 7.5% 仓位上限最均衡**。
- 第一批纸面跟踪应优先观察 **5% 和 7.5%**，10% 只作为更进攻的对照组。
- 如果 BTC 长期没有正收益，或者核心三资产同时失效，这个增强结构也会失去价值。

详细结论见 [Q10 实盘化压力测试与执行规则复盘](docs/notes/q10-live-readiness-stress-review.md)。

### Theme Alpha

核心风险平价 + 低波趋势主题卫星的组合，重点优势不是收益最高，而是风险调整后的稳定性更好。以下为 2020 年以来真实 ETF 数据。

默认候选：`80% 核心风险平价 + 20% LVT 卫星 + 200 日均线现金防守`

| 策略变体 | 年化收益 | 最大回撤 | 夏普 | 卡玛 |
|---------|-------:|-------:|----:|----:|
| 三资产 RiskParity（基准） | 14.58% | -15.38% | 1.15 | 0.95 |
| **Core80 + LVT20（推荐）** | **14.48%** | **-11.29%** | **1.38** | **1.28** |
| Core60 + LVT40 | 15.56% | -13.97% | 1.40 | 1.11 |

- **不建议全仓做主题轮动**。更长的代理数据表明，LVT 并不是每个市场阶段都有效，适合做卫星，不适合做主引擎。
- 40% 主题卫星更进攻，但还不适合作为默认方案；下一步更值得测试的是 30% 中间档。
- SuperTrend 可以作为第二层风险确认，但目前没有足够证据替代原有 LVT 规则。

详细结论见 [Theme Alpha 长样本与代理验证](docs/notes/theme-alpha-q12-long-sample-proxy-validation-review.md)。

## 快速开始

### 查看策略仪表盘

需要 Node.js（>= 18）和 npm。项目根目录下有 `Makefile`，以下命令均在根目录执行。

首次运行：

```bash
make dashboard-install
make dashboard
```

终端会显示本地访问地址。日常启动使用本地研究结果，不会主动下载最新行情。

如果需要刷新外部基准数据后再启动：

```bash
make dashboard-dev-fresh
```

该命令需要网络连接。提交仪表盘改动前可运行：

```bash
make dashboard-check
```

### 查看或运行研究 Notebook

项目使用 Python 3.12+。首次安装或依赖发生变化时：

> 本项目使用 [uv](https://github.com/astral-sh/uv) 管理 Python 环境。如未安装：`curl -LsSf https://astral.sh/uv/install.sh | sh`

```bash
uv sync
```

`uv sync` 会根据 `pyproject.toml` 和 `uv.lock` 创建或更新 `.venv`。验证环境并启动：

```bash
uv run python check_env.py
uv run pytest
uv run jupyter lab
```

`check_env.py` 会检查 pandas、NumPy、Matplotlib、AkShare、yfinance、open-xquant 和数据接口是否可用。

## 目录说明

```text
.
├── pyproject.toml     # Python 项目与直接依赖
├── uv.lock            # 可复现的精确依赖版本
├── .python-version    # uv 默认使用的 Python 版本
├── src/xquant/        # 经过测试的公共研究函数
├── tests/             # Python 单元与集成测试
├── research/          # Notebook 研究索引与实践文件
├── scripts/           # 可重复运行的完整研究任务
├── outputs/           # 经过筛选的研究结果快照
├── docs/              # 复盘、计划与结构说明
└── dashboard/         # React 策略报告与数据转换脚本
```

公共计算应放入 `src/xquant/`，Notebook 负责组织实验和展示结果。Notebook 的后续迁移方式与输出保留边界，见 [仓库结构说明](docs/repository-structure.md) 和 [研究输出保留规则](outputs/README.md)。

## 风险提示

> [!WARNING]
> - 回测结果不代表未来收益，尤其不能把近几年有利的黄金、纳指或 BTC 行情直接外推。
> - 长样本中的海外代理 ETF 与境内 ETF 在币种、交易时间和成分上并不相同，只能用于检查结构，不能当作可交易结果。
> - 当前成本、滑点和延迟测试仍未覆盖所有真实交易限制。
> - "历史收益最高"和"最适合继续执行"不是同一个答案；本项目默认优先考虑后者。
