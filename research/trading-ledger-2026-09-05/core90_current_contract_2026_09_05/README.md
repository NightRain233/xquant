# 修复后的 Core90 + MA200 Bull10 历史基准

本研究从恢复的 81 份 OHLCV 重新生成当前合同的月度选池、完整日线 ST 7/3 翻转、
MA200 准入与退出决策，再通过与 paper 服务共用的逐日循环和执行引擎生成交易、持仓、现金和净值。
不使用旧 xquant 的决策事件或交易作为信号输入。

## 本次结果

| 结果来源 | 年化收益 | Sharpe | 最大回撤 | 可用范围 |
|---|---:|---:|---:|---|
| 恢复的原 xquant 研究 | 16.28% | 1.43 | -13.49% | 旧研究合同 |
| 当前合同 2.0.0 诊断回放 | 15.25% | 1.33 | -12.66% | 数量守恒失败，不作为有效基准 |
| 修复后 2.1.0 | **14.98%** | **1.30** | **-12.66%** | 本文限定范围内的新历史基准 |

修复版 100,000 元变为 499,435.13 元，样本包含 4,209 个日历日期。
指标保留各来源记录口径：2.0.0 诊断含前一日现金激活行，2.1.0 指标从样本开始日计；
新版本 Sharpe 按样本观测密度年化、无风险收益设为零。
这些差异不能全部归因于 sleeve 修复：旧研究与当前合同还存在选池、FX 阻断及组合预算差异。

全历史审计：持仓数量不一致 **0 行**，现金最大绝对误差 **5.98e-10 元**，
成交日期不晚于信号日期 **0 笔**。trading 后端回归测试 **500 通过、6 跳过**，xquant 研究测试 **55 通过**；
跳过项受本机行情缓存范围限制，不纳入通过证明。封存源码的 28 个文件哈希与本次实际运行文件一致（trading 代码和 xquant 编排脚本分别带有仓库前缀）。

入场订单对照：原独立卫星研究 471 笔，当前组合卫星 326 笔，
按“标的 + 实际成交日”匹配 89 笔。其余逐行列在 `comparison/`，匹配数量不代表信号正确率。

## 版本与修复范围

主策略版本升级为 **2.1.0**，信号合同仍为 `bull_flip_ma200_v1`，执行合同新增
`proportional_next_open_v1`。核心 90%、卫星 10%、MA200 窗口、ST 参数及选池门槛未调参。
Raw Bull10 保留既有版本，本轮没有迁移其执行合同，不能直接把两者的差异归因于 MA200。

修复前 2.0.0 的再平衡通过按比例直接修改持仓数量恢复 sleeve 比例，没有对应的市场成交，
而且基于前收盘估值；其完整回放有 **30,448 行“持仓无法从成交还原”的记录**。
这不是 30,448 笔错误订单，而是跨估值日期持续出现的数量守恒失败。
修复前产物保存在 `before_2_0/`，不得作为通过验证的结果。

2.1.0 的实际执行：

1. 冻结核心配置目标后，在下一可成交开盘按总资产开盘估值恢复 90/10 预算。
2. 卫星按已有持仓/现金比例调整，每次股数变化都生成父配置决策下的 `SLEEVE_RESIZE` 子订单和成交。
3. sleeve 调整费用仍为 10 bps，以实际调整名义金额记录在成交费用中；现金跨 sleeve 转移不重复收费。
4. 核心按冻结目标权重再平衡并单独扣除原核心费用，因此费用后权重可能有微小偏离。
5. 有卫星缺失或受限开盘时，整笔预算再平衡等待；卫星退出后释放限制也不能将核心成交回写到过去。
6. D 日决策在 D+1 UTC 零点后冻结，届时同日参考市场已收盘、CNY 下一开盘尚未发生。
   夜间早于该时点不会因同日美股参考尚未收盘而永久拒绝信号。
7. research 与 paper 共用 `advance_current_contract`，按账户 checkpoint 逐日恢复，不跳过漏跑的核心再平衡。

这是改变实际成交结果的执行修复，采用新账户版本，不回填已有 2.0.0 账户历史。
本轮没有部署、激活或修改线上账户。

## 数据范围和假设

- 样本：2015-01-01 至 2026-07-10；激活日为 2014-12-31，全现金，初始资金 100,000 CNY。
- 81 个本地可观察候选，不是完整历史证券主表；选池按当时历史重新计算。
- 保留生产合同的 2026-07-01 单次冻结成员快照，其出处在 fixture 和源码哈希中。
- 外币标的因缺少 FX/可投资载体合同而阻断新仓；境内 CNY 上市的海外资产代理按当前配置处理。
- 开盘状态字段可用于约束成交，但恢复的历史行情没有完整停牌/涨跌停开盘状态主表。
  没有状态字段时沿用有限正数 Open 假设，不从当日收盘/最高/最低/全天量反推开盘可成交性。
- 以日 K 日期为事件标签，D+1 UTC 零点为日决策可知时点，非逐笔成交模型。
- NAV 包含日历日期，休市资产沿用最近有效价格；未模拟税制、订单簿冲击、实际券商最小手数和 ETF 溢价。

因此通过的结果应称为：**修复后主策略在有限可观察标的池、上述执行假设下的历史验证**。
它不等同于完整 PIT 市场验证、样本外盈利验证或实盘授权。

## 重跑

研究编排和历史产物位于 xquant；成交、持仓和净值仍调用 trading 的执行内核。
在 xquant 根目录执行：

```bash
cd /Users/zz/Desktop/Code/zsd/xquant
/Users/zz/Desktop/Code/zsd/trading/backend/.venv/bin/python \
  research/trading-ledger-2026-09-05/core90_current_contract_2026_09_05/recompute.py \
  --trading-root /Users/zz/Desktop/Code/zsd/trading \
  --output /tmp/core90-current-new
```

输出路径必须不存在。运行会验证原始压缩包哈希，读取其中 OHLCV，并在输出路径建立全新 SQLite 研究账本。
代码不访问行情 API，不使用生产账本；研究包从 xquant 读取封存行情，执行内核从 trading 读取。
`manifest.json` 记录配置、原行情包 SHA256、源码逐文件哈希、基础 Git 提交及执行假设；
`source_bundle.zip` 封存本次实际运行的策略源码，避免未提交工作区变化造成出处漂移。
若工作区代码已更新，先在独立目录检出 manifest 的 `baseGitCommit`，复制本研究目录和
`core90_recovery_2026_09_05/`，再在同时包含 `trading/` 与 `xquant/` 的父目录解压
`validated_2_1/source_bundle.zip`（压缩包内有 `trading/`、`xquant/` 两个前缀），按上述锁定依赖的命令重跑。
不要将封存源码覆盖到正在使用的生产目录。

`validated_2_1/` 中保存：

- `decisions.csv`、`decision_items.csv`：逐信号与拒绝原因；
- `universe.csv`、`memberships.csv`：逐月选池依据；
- `orders.csv`、`fills.csv`、`attempts.csv`：完整订单、成交、延迟；
- `positions.csv`、`daily_nav.csv`、`sleeve_transfers.csv`：持仓、净值和现金转移；
- `quantity_reconciliation.csv`、`cash_reconciliation.csv`：守恒校验；
- `metrics.json`、`checkpoints.csv`：指标、审计状态与逐日恢复记录。

SQLite 可由重跑生成，版本化研究包保存 CSV 和源码，不重复提交数据库。

```bash
/Users/zz/Desktop/Code/zsd/trading/backend/.venv/bin/python \
  research/trading-ledger-2026-09-05/core90_current_contract_2026_09_05/compare.py \
  --current research/trading-ledger-2026-09-05/core90_current_contract_2026_09_05/validated_2_1 \
  --output /tmp/core90-comparison-new
```

`comparison/` 提供旧研究入场订单与修复版入场订单的对照，以及 2.0.0/2.1.0 逐日 NAV 差异。
旧研究卫星交易和当前组合预算约束不同，匹配键为“标的+实际入场日”；不假装单一修复解释全部差异。

## 验收

自动化检查覆盖：逐日 paper 与历史回放成交/NAV 一致、停机一次性恢复与连续运行一致、
重复刷新不重复下单、未来价格不改变此前决策、成交日收盘不影响开盘成交、停牌等待、
退出解除限制不倒填成交、开盘跳空下数量及现金守恒、UTC 确认时点、激活前不产生估值。

本轮研究基线至此冻结，研究阶段可以先告一段落。walk-forward、集中度和参数稳定性属于下一次独立研究；
如果重新启动，必须使用新版本号和新输出目录，不在本基线上反复试参数。
